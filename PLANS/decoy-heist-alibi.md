# 12. 알리바이 하이스트

## 1. 한 줄 컨셉

경비는 침입자가 몇 명인지 모른다. 과거의 나를 미끼로 던져 시야를 사고, 그 사이에 금고를 연다.

## 2. 장르 / 회차 구조

- 장르: 실시간 탑다운 잠입 퍼즐. 턴제 아님. 경비 시야와 순찰이 연속 시간축 위에서 계속 움직인다.
- 시점: 고정 화면 1~2개 방. 벽 뒤는 보이지 않지만 경비 시야 콘은 항상 표시된다(정보 은닉으로 난이도를 만들지 않는다).
- 회차 구조: 한 스테이지 = 최대 8회차. 각 회차는 동일한 45초 타임라인을 공유한다.
- 회차 N에서는 회차 1~N-1의 나가 전부 동시에 재생된다. 경비는 이들을 **전부 침입자로 인식한다.**
- 고스트가 경비에게 잡히면 그 고스트는 그 시점에 소멸하고, 잡은 경비는 3.0초 동안 그 자리에 정지한 뒤 순찰로로 복귀한다. 이 3.0초가 플레이어가 사는 시간이다.

## 3. 핵심 루프

1. 라운드 시작. 45초 카운트다운.
2. 플레이어는 이동(8방향, 정수 방향 벡터) + 달리기(홀드, 속도 1.6배·소음 반경 발생) + 상호작용 홀드 1키만 쓴다.
3. 경비 시야 콘에 1틱이라도 들어가면 그 대상은 "발각"되고 경비가 추격을 시작한다. 접촉 시 체포.
4. 플레이어가 체포되면 그 회차는 즉시 종료되고, **체포된 시점까지의 기록이 그대로 고스트로 남는다.** 체포는 실패가 아니라 미끼 자원의 생성이다.
5. 금고는 2인 동시 조작(양쪽 레버를 동시에 4.0초 홀드)이 필요하다. 즉 최소 한 명의 고스트가 반대편 레버를 잡고 있어야 한다.
6. 금고를 열고 탈출구에 도달하면 클리어.

경비 상태 머신(결정론적, 난수 없음):

| 상태 | 진입 조건 | 행동 | 이탈 조건 |
| --- | --- | --- | --- |
| 순찰 | 기본 | 고정 웨이포인트 순회, 속도 60px/s | 시야 내 대상 감지 / 소음 감지 |
| 추격 | 시야 콘 내 대상 1틱 이상 | 대상 좌표로 직선 이동, 속도 95px/s | 대상 체포 / 대상 소실 후 4.0초 |
| 조사 | 소음 발생 지점 인지 | 소음 좌표로 이동 후 2.0초 두리번 | 2.0초 경과 |
| 복귀 | 체포·조사 종료 | 가장 가까운 웨이포인트로 이동 | 웨이포인트 도달 |

**대상 선택 규칙(결정론 핵심):** 시야 내 대상이 여럿이면 **회차 번호가 가장 낮은 대상**을 고른다. 거리 비교가 아니라 회차 번호 비교다. 정수 비교이므로 부동소수점 타이브레이크 문제가 원천 차단되고, 플레이어가 "가장 오래된 나가 미끼가 된다"는 규칙을 예측할 수 있다.

## 4. 과거 자신과의 상호작용

**기록 방식: 위치 스냅샷.** 이 게임만 입력 로그를 쓰지 않는다. 이유가 명확하다. 경비 AI가 고스트에 반응하므로 회차마다 경비의 움직임이 달라지고, 입력 로그를 재생하면 이전 회차의 나가 "그때와 다른 경비"에 부딪혀 다른 궤적을 그리게 된다. 그러면 플레이어가 세운 계획이 무너진다. **고스트의 궤적은 불변 데이터여야 한다.**

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 시뮬레이션 틱 | 60Hz 고정 | 경비 시야 판정 정밀도 확보 |
| 기록 주기 | 초당 20회(3틱마다 1회) | 이동 속도 60~96px/s에서 50ms 간격이면 최대 4.8px 오차, 선형 보간으로 육안 구분 불가 |
| 스냅샷 1건 크기 | 6바이트 | x:int16, y:int16, 상태:uint8(정지/걷기/달리기/홀드/체포), 방향:uint8(0~7) |
| 1회차 제한 시간 | 45.0초 = 2700틱 = 900스냅샷 | 잠입은 관찰 시간이 필요하다. 30초는 순찰 1주기를 못 본다 |
| 회차당 기록 크기 | 5,400바이트 | 900 × 6 |
| 동시 재생 고스트 최대 | 7 (플레이어 포함 8명) | 경비 3~5명 기준, 8명 넘으면 미끼가 과잉 공급되어 퍼즐이 붕괴 |
| 전체 메모리 사용 | 8 × 5,400 = 43.2KB | 메모리 전용, 파일 기록 없음 |

**결정론적 재현 보장 방법:**

1. 고스트는 **순수 재생 객체**다. 물리도 AI도 없고 스냅샷 사이를 정수 보간해 그려질 뿐이다. 고스트의 궤적은 회차가 몇 번 반복되든 100% 동일함이 자명하게 보장된다. 이 게임에서 결정론 리스크는 고스트 쪽에 존재하지 않는다.
2. 결정론이 필요한 대상은 **경비 AI뿐**이다. 경비 좌표는 16.16 고정소수점, 시야 판정은 정수 내적 + 정수 제곱거리 비교, 벽 가림 판정은 타일 격자 DDA(정수 연산)로 처리한다. 부동소수점 미사용.
3. 경비 업데이트 순서는 경비 인덱스 오름차순 고정. 대상 선택은 위 규칙대로 회차 번호 최소값(정수)이므로 타이브레이크 모호성이 없다.
4. 난수 없음. 순찰 웨이포인트는 스테이지 데이터에 고정.
5. **경비는 매 회차 처음부터 다시 시뮬레이션된다.** 이는 의도된 설계이며 리스크이기도 하다(10절 참조). 검증은 "고스트를 0명 놓고 같은 회차를 두 번 돌렸을 때 경비 궤적 CRC32가 일치하는가"로 자동 테스트한다.

**패러독스 처리:** 고스트는 경비를 막지 않고 통과시키지 않는다(체포될 뿐이다). 고스트끼리는 통과한다. 고스트가 이번 회차에 더 일찍 잡혀 기록보다 짧게 끝나는 경우는 발생하지 않는다 — 고스트는 기록된 궤적을 끝까지 재생하며, 이번 회차에 경비에게 잡히면 그 지점에서 **소멸**한다(궤적이 잘릴 뿐 다른 곳으로 튀지 않는다). 따라서 "예상보다 일찍 사라질 수는 있어도, 예상과 다른 곳에 가 있을 수는 없다." 이 한 문장이 플레이어의 계획 가능성을 지킨다.

## 5. 승리 조건

- 스테이지 클리어: 한 회차 안에서 금고 개방(양쪽 레버 4.0초 동시 홀드) 후 현재 플레이어가 탈출구 타일에 도달한다. 고스트가 탈출구에 도달하는 것은 클리어로 치지 않는다.
- **총 회차 수: 스테이지당 최대 8회차.** 8회차에서도 실패하면 스테이지 재시작(모든 고스트 소거).
- 45초가 지나면 자동으로 회차 종료. 체포되면 즉시 회차 종료.
- 등급: 미끼로 희생시킨 회차 수가 적을수록 높은 등급.

## 6. 대표 퍼즐 예시

### 퍼즐 A: "복도의 두 눈" (목표 3회차)

배치: 좌우로 긴 복도. 경비 A는 복도를 좌↔우 왕복(편도 12초). 금고는 복도 끝 방에 있고 레버는 방 양쪽 벽에 하나씩. 탈출구는 시작 지점 반대편.

| 시각 | 경비 A | 회차1 (미끼) | 회차2 (미끼) | 회차3 (현재) |
| --- | --- | --- | --- | --- |
| 0.0s | 좌→우 이동 시작 | 복도로 뛰어들어 일부러 노출 | 숨어서 대기 | 숨어서 대기 |
| 2.5s | 회차1 발각, 추격 시작 | 좌측으로 도주 | - | - |
| 6.0s | 회차1 체포, 3.0초 정지 | **소멸** | 금고방으로 이동 시작 | - |
| 6.0s | - | - | - | 금고방으로 이동 시작 |
| 9.0s | 복귀 시작(웨이포인트까지 5초) | - | 좌측 레버 앞 도착 | 우측 레버 앞 도착 |
| 9.5s | - | - | 레버 홀드 시작 | 레버 홀드 시작 |
| 13.5s | 순찰 재개, 금고방 진입 중 | - | **금고 개방 완료** | 금고 개방 완료, 아이템 획득 |
| 14.0s | 회차2 발각(회차 번호 낮음) | - | 그 자리 홀드 유지 → 체포 | 탈출로로 이동 |
| 17.0s | 회차2 체포, 3.0초 정지 | - | 소멸 | - |
| 21.0s | - | - | - | 탈출구 도달 → **클리어** |

핵심: 미끼를 **두 번** 써야 한다. 첫 번째는 금고방 진입 시간을 벌기 위해, 두 번째는 탈출 시간을 벌기 위해. 그리고 회차2는 미끼인 동시에 레버 담당이다. 하나의 과거가 두 역할을 겸하는 순간이 이 퍼즐의 정답 감각이다.

### 퍼즐 B: "동시에 세 곳" (목표 5회차)

배치: 중앙 홀에 경비 3명이 삼각형으로 배치되어 각자 다른 방향을 본다. 시야 콘 3개가 홀 전체를 덮어 사각지대가 없다. 금고는 홀 중앙. 소음 유발용 유리창이 홀 외곽 3곳에 있다(달리기로 통과하면 깨지며 소음 발생).

| 시각 | 이벤트 |
| --- | --- |
| 0.0s | 회차1: 북쪽 유리창을 달려 통과 → 소음. 경비1 조사 상태 진입(왕복 8초 소요) |
| 1.5s | 회차2: 동쪽 유리창 통과 → 소음. 경비2 조사 상태 진입 |
| 3.0s | 회차3: 서쪽 유리창 통과 → 소음. 경비3 조사 상태 진입 |
| 3.0~9.0s | 홀 중앙 시야 공백 발생(경비 3명 전원이 외곽에 있음) |
| 4.0s | 회차4: 중앙 좌측 레버 도착, 홀드 시작 |
| 4.2s | 회차5(현재): 중앙 우측 레버 도착, 홀드 시작 |
| 8.2s | 금고 개방 완료 |
| 9.0s | 경비들 복귀 시작 — 회차4가 여전히 레버 자리에 서 있어(기록상 홀드 유지) 경비1의 첫 표적이 됨 |
| 12.0s | 회차4 체포, 경비1 3초 정지 |
| 15.0s | 회차5 탈출구 도달 → **클리어** |

핵심: 소음 유발 타이밍을 **1.5초씩 어긋나게** 배치해야 한다. 세 창을 동시에 깨면 경비 3명이 같은 시각에 복귀해 중앙 공백이 6초가 아니라 4초로 줄고 개방(4.0초)이 아슬아슬해진다. 시차 배치가 공백 창을 늘린다는 발견이 이 퍼즐의 정답이다. 또한 회차4는 레버를 잡고 있느라 도망칠 수 없으므로 애초에 희생 전제로 설계된다.

## 7. 로그라이크 요소

없음. 경비 순찰로와 배치가 완전 고정이어야 플레이어의 관찰-계획-실행 루프가 성립한다. 난수를 넣는 순간 잠입 퍼즐이 아니라 운 게임이 된다.

## 8. 1.44MB 적합성

| 구분 | 예상 크기 | 근거 |
| --- | --- | --- |
| 코드/런타임 | 140~200KB | Win32 + 소프트웨어 렌더러. 시야 콘 렌더링(정수 DDA 기반 폴리곤 채우기)과 경비 FSM이 추가 코드를 요구해 11번안보다 다소 크다 |
| 그래픽 | 10~20KB | 16×16 타일 아틀라스 1장. 시야 콘은 런타임 생성(에셋 0바이트). 캐릭터는 회차별 팔레트 스왑 |
| 사운드 | 8~15KB | 런타임 합성. 발소리·유리 깨짐·경보 등 SFX 10종 파라미터 테이블 + 저음 긴장 BGM 시퀀스 |
| 데이터 | 5~12KB | 스테이지당 타일맵 + 경비 웨이포인트 배열(경비 5명 × 8점 × 4바이트 = 160바이트) + 오브젝트 배치. 스테이지 20개 기준 10KB 내외 |
| **합계** | **165~250KB** | 상한의 약 17% |

고스트 기록은 **파일 용량 0바이트**, 런타임 메모리 최대 43.2KB다. 스냅샷 방식이라 11번안보다 메모리를 2배 이상 쓰지만 절대량이 작아 문제되지 않는다.

## 9. 3주 구현 난이도

**판정: 중.**

- 고스트 쪽 결정론 리스크는 **사실상 0**이다. 스냅샷 재생이라 재현 오차가 발생할 구조가 아니다. 이것이 이 안의 최대 기술적 장점이다.
- 대신 위험은 **경비 AI의 재현성**으로 옮겨간다. 경비가 매 회차 재시뮬레이션되므로, 시야 판정이나 경로 이동에 부동소수점이 한 줄이라도 섞이면 회차마다 미묘하게 다른 행동이 나오고 플레이어는 이유를 알 수 없는 실패를 겪는다. 3주 안 안정화 위험도: **중.** 정수 연산 원칙을 1주차에 못박고 "고스트 0명 이중 실행 CRC 비교" 자동 테스트를 붙이면 관리 가능하다.
- 추가 리스크: 경로 탐색을 넣으면 난이도가 급상승한다. **A*를 쓰지 않는다.** 추격은 직선 이동 + 벽 슬라이딩만 사용하고, 벽이 많은 구조는 레벨 디자인으로 회피한다. 이 결정이 3주 완주의 전제다.

주차별:
- 1주차: 고정 틱 루프, 스냅샷 기록/재생, 경비 FSM 3상태, 정수 시야 판정, CRC 테스트.
- 2주차: 체포/소멸/복귀 규칙, 소음 시스템, 2인 레버 금고, 회차 관리 UI.
- 3주차: 스테이지 제작, 시야 콘 시각화 폴리싱, 사운드, 튜토리얼.

## 10. 재미 포인트와 리스크

**재미 포인트**
- "일부러 잡힌다"는 역발상이 강렬하다. 잠입 게임에서 발각은 항상 실패였는데, 여기서는 자원 생산이다. 컨셉 한 줄로 설명되고 즉시 이해된다.
- 회차 번호가 낮은 쪽이 표적이 되는 규칙 덕분에, 플레이어는 "가장 오래된 나를 방패로 쓴다"는 서사를 자연스럽게 느낀다. 주제인 과거와의 상호작용이 기계적으로도 정서적으로도 맞물린다.
- 실시간이므로 경비 시야 콘이 스치듯 지나가는 0.5초의 긴장이 그대로 손끝에 온다.
- 미끼 회차와 작업 회차를 겸하는 배분 문제는 회차 수가 늘수록 조합이 풍부해진다.

**리스크**
- **경비 재시뮬레이션의 나비효과가 가장 큰 위험이다.** 회차 5에서 고스트 하나가 1초 늦게 잡히면 경비 복귀 시각이 밀리고, 그 뒤 모든 계획이 어긋난다. 이는 재미(긴장)이면서 동시에 "왜 실패했는지 모르겠다"는 좌절의 원천이다. 완화책: 경비 복귀 시간을 고정 3.0초로 못박고, 체포 시각이 밀려도 순찰 웨이포인트 복귀 후에는 항상 원래 순찰 위상으로 스냅되도록 설계한다. 이 위상 스냅 규칙을 반드시 넣어야 한다.
- **사각지대 정보 문제.** 벽 뒤 경비의 시야를 보여줄지 말지에 따라 게임이 완전히 달라진다. 항상 표시하기로 결정했으나, 화면이 시야 콘으로 뒤덮여 지저분해질 수 있다. 콘 알파를 낮추고 경계선만 강조하는 표현이 필요하다.
- **관찰 시간의 지루함.** 첫 회차는 아무것도 못 하고 순찰만 보는 45초가 될 수 있다. 관찰 전용 빨리감기(고스트 없는 상태에서 2배속 미리보기)를 넣을지 판단이 필요하나, 넣으면 결정론 검증 대상이 하나 늘어난다. 3주 일정에서는 넣지 않는 쪽을 권한다.
- 소음 시스템까지 넣으면 경비 상태가 4개가 되어 디버깅 표면적이 커진다. 일정이 밀리면 조사 상태를 잘라내고 시야 감지만 남기는 축소안을 미리 준비해야 한다.
